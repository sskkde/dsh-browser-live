# 跨会话登录态与文件共享执行方案

- 日期：2026-11-10（Asia/Shanghai）。
- 状态：**方案已落盘，尚未实施；不代表已完成开发、迁移或运行验收。**
- 已确认方向：独立浏览器＋共享登录态仓库＋共享文件库，不采用所有会话共用同一个 Chromium。
- 本轮授权边界：仅编写文档；不修改产品代码、不清理容器或数据、不部署、不重启、不提交或推送。
- 下文接口、目录、配置和模块名标为“拟新增”的均是设计契约，不是当前已有能力。

## 1. 目标与使用体验

同一用户明确授权的可信会话之间：

1. 会话 A 登录某网站并将该账号发布到共享仓库；会话 B 绑定同一账号后，可以恢复受支持的登录态，减少重复登录。
2. A 产生的下载、截图，可由 B 通过统一工具查询并复制到自己的工作目录；不需要知道 A 的容器名、槽位或宿主路径。
3. A、B 的窗口、标签页、浏览器进程和配置卷仍独立；A 导航、关闭标签页不会操控 B。
4. 容器回收不删除已发布的登录态和文件；清理浏览器运行资源与清理共享数据是两项独立操作。
5. 经共享接口访问时，未授权会话、不同共享范围、不同账号不能因“在同一个 DSH 进程里”而自动共享；对任意宿主读文件/CDP 权限的隔离限制见 3.1。

不承诺：浏览器完整克隆、实时同步全部浏览器存储、绕过验证码/风控、登录永久有效，或跨设备自动保持设备绑定凭据可用。

## 3. 总体架构与信任边界

```text
可信会话 A ── 独立 Chromium A / 独立 profile / 私有下载暂存区
                 │
                 ├─ SessionAccessCoordinator（拟新增：鉴权、初始化、操作锁、操作后采集）
                 │      ├─ AuthStateStore（按共享范围＋站点＋账号发布不可变版本）
                 │      └─ ArtifactStore（共享索引＋不可变文件对象）
                 │
可信会话 B ── 独立 Chromium B / 独立 profile / 私有下载暂存区
```

### 3.1 共享范围（scope）

- 采用管理员维护的 `trusted-group` 范围：共享的是同一可信用户授权的一组会话，不是全机器、全账号或全部 Agent。
- 会话到范围的映射必须由可信宿主身份/管理员策略解析。不得使用工具参数中的任意 `scopeId`、工作目录或模型自报用户名作为权限凭据。
- 子代理不自动继承登录态权限；只有策略明确允许的子代理才加入对应范围。与父会话同目录不等于有权限。
- 预检必须先验证宿主是否提供可用的用户/会话身份。若当前部署只有单一进程账号，范围只能声明为“此专用 profile 内管理员显式列入的可信会话”，不能宣称实现多租户隔离。
- 共享范围内的会话被视为可使用账号和读取文件的受托主体。拿到登录态等同于获得相应网站权限；分组、撤销与审计必须优先于便利性。
- 文件工具和登录态工具每次调用都校验范围；原生工具、MCP 常驻工具、能力组工具及 gateway_call 均不能绕过。网关模式需解析 `exec.arguments.tool` 中的实际工具名，而非只检查外层 gateway_call；Cookie/storage 读、写、清除均在策略覆盖内。
- **这只是应用层访问边界，不是同 UID 任意代码执行的安全沙箱。** 若会话能用 read/bash 任意读取宿主凭据目录、访问其他容器 CDP，或持有 Docker socket，插件内的 scope 校验无法阻止窃取。首版部署前提是同 profile 内所有此类主体都可信；不可信主体必须隔离 OS 用户/进程、文件挂载、CDP 网络与 Docker 权限，并验证无共享凭据旁路。0700/0600 也不能隔离相同 UID。A07 必须区分接口拒绝与系统级隔离，不能混为已实现的多租户安全。

### 3.2 建议配置（拟新增，不可直接用于当前版本）

```yaml
sharing:
  enabled: false                 # 升级安装后默认关闭；验收后对指定可信范围开启
  scopeMode: trusted-group
  artifactAutoPublish: true      # 仅对已授权范围中的受管浏览器产物
  authAutoRestore: true          # 仅恢复已显式绑定并允许的账号
  authAutoPublish: false         # 初版默认显式保存；正向登录校验通过后才可按站点启用
  retentionDays: 0               # 0 表示不按时间自动删除，非无限容量承诺
  quotaBytes: null               # 投产前按磁盘盘点配置；未设置只告警，不自动删除旧数据
```

网站/账号绑定、可信会话列表及授权策略由管理配置维护，不交给网页内容或模型自动批准。默认值是方案建议，实施批准时一起确认；不得把它们当成用户已批准开启全局共享。

## 4. 独立浏览器与资源池改造

1. 新策略下所有槽位（包括 0）都用会话专属容器名、专属 profile 卷、专属 viewer 路径。槽位仅决定端口，不决定是否共享历史状态。
2. 新会话绝不再接管 legacy `neko`。旧容器先作为迁移源留存、从新池排除；不得把旧 map 的 `legacy` 标志直接改为 false 后继续运行。
3. 新版 map 使用明确版本及实例 generation，包含 session、slot、container、profile、策略版本等；旧映射由迁移流程处理，不能静默就地覆写。
4. 回收必须等待在途浏览器操作结束或获得回收锁；LRU 不得淘汰 busy/leased 实例。池满且全忙时返回明确的“容量不足/稍后重试”，不杀正在操作的浏览器。
5. 回收状态机为 `active → draining → deleting → released`；容器和相关入口实际释放后才能复用槽位。失败保留待重试的回收记录，不先删映射导致失联。
6. 启动时按受管标签和 map 双向对账，发现未知/失联容器只报告；不对名字相似的容器批量删除。跨代回收须核对实例 generation，避免删掉已重新分配的容器。
7. TTL 仍管理浏览器运行资源；共享登录态和产物不随 TTL 删除。热重载/宿主重启可以继续接管健康的会话专属实例。
8. 旧 `neko` 仍运行时，必须预留其 CDP 9222、Web 8080 及实际 WebRTC 端口。新槽位 0 不得继续硬套旧端口；执行时选择无冲突的新端口区间并持久化映射，或经授权停止旧实例后再复用。不能只换容器名。

这些改动是共享方案的前置安全门禁：否则分到 0 号槽位仍有串号风险，异步回收也可能打断正在提交的文件。

## 5. 登录态仓库设计

### 5.1 数据模型与存储

拟新增存储根：`<DSH_HOME>/data/browser-live/shared/v1/scopes/<scopeId>/auth/`。

逻辑主键：`scopeId + siteKey + accountKey`。

- 所有物理路径组件（scopeId、artifactId、revision 等）均使用服务端生成或严格校验的 opaque ID/安全编码；siteKey、accountKey 是逻辑标识，不能直接当路径。写入和读取均校验 canonical root containment，以安全文件打开方式拒绝符号链接/路径穿越及检查后的替换竞态；网页、下载名、Content-Disposition 和工具参数都不是可信路径来源。
- `siteKey` 是管理员定义的站点策略标识，映射精确的允许 origin、Cookie 域和必要的 SSO origin；不得简单按字符串后缀或同一主域名自动扩权。
- `accountKey` 是不含凭据的账号别名。一个会话在同一站点只绑定一个账号；禁止静默覆盖为共享仓库“最新账号”。Cookie/SSO 域冲突的账号绑定必须拒绝或使用另一个独立浏览器。
- 每次发布创建不可变 revision，记录格式版本、站点/账号标识、来源会话、捕获时间、基础 revision、撤销 epoch 和能力声明。
- Cookie/localStorage 是最低支持集。IndexedDB 仅在 P0 验证已安装 Playwright 与 CDP 默认 context 的导出/导入链路完整后纳入；不支持时明确报告，不写成已实现。
- sessionStorage、Passkey、扩展存储、设备绑定凭据、浏览器证书等不在初版保证范围。
- 密钥数据目录权限 0700、状态文件 0600；日志、工具返回、文件索引中不输出 Cookie/token/localStorage 原文。磁盘加密或 KMS 属额外部署能力，未启用时不得宣称静态加密。

### 5.2 首次绑定、恢复与保存

1. A 在自己的浏览器正常登录，不通过共享仓库存储密码。
2. 用户显式确认站点、账号及共享范围后，通过保留的 `browser_live_state save` 入口发布首个 revision；只导出站点允许范围，不能沿用当前“整 context 全部 Cookie”无过滤存取。
3. B 首次绑定此账号时，在实际操作/首个业务请求前加载已发布 revision。Cookie 先写入；localStorage 在目标 origin 页面脚本读取前初始化。不能通过先访问业务页再回填的方式声称“首请求已恢复”。
4. 只读 `status`、文件查询不应导入登录态、创建浏览器、访问网站或刷新浏览器空闲计时。
5. 同一浏览器实例只在首次绑定、实例重建或用户明确刷新时恢复。普通每次调用不重复覆盖本地 Cookie/localStorage，避免反复回滚当前登录过程。
6. 活跃 B 不自动接收 A 新发布版本，避免运行中账号被替换；B 下次创建实例或显式刷新时读取新版本，并返回当前使用的 revision。
7. 原生工具和 MCP 都经同一个协调器：在保证容器就绪后、执行网页操作前准备登录态；操作后采集候选更新。MCP 通过 gateway_call 间接调用也必须覆盖。
8. UI 内手工登录不一定伴随工具调用。初版提供显式保存/发布按钮或工具；若启用手工登录自动采集，必须独立验证页面事件和用户确认链路，不依赖 agent 回合结束或容器销毁时才保存。

**恢复能力探针是硬门禁：** 已安装版本若存在可对 CDP 默认 context 完整恢复的官方 API，先验证再采用；否则验证受控 CDP/新文档初始化方案。必须覆盖新标签页、重定向、既有页面和清理初始化钩子，防止旧快照在后续导航反复写回。未通过时可保留显式 load 的受限兼容功能，但不得按“自动登录态恢复完成”放行。

### 5.3 并发、过期与撤销

- 发布采用按主键互斥＋`expectedRevision` 乐观校验＋临时文件原子 rename；旧 revision 不覆盖新 revision。不采用无条件最后写入者获胜。发布与撤销共用同一主键提交锁，发布在最终提交临界区同时核对 expectedRevision、当前撤销 epoch 和授权状态；不能只在加载快照时检查 epoch。
- 冲突返回当前 revision 和冲突标识，不跨账号合并 Cookie、不自动重试覆盖。共享仓库初版限定单写入宿主进程；若允许多个 DSH 进程，必须先实现跨进程锁/CAS 并通过竞争测试。
- 自动发布初版默认关闭。站点明确配置正向已登录检查后，才允许同一绑定的健康浏览器自动刷新候选版本；登录失败、验证码、重定向到登录页或工具失败不得发布为空状态或覆盖健康版本。
- 远端 session/token 过期时，报告需要重新登录；不连续重放凭据、不尝试绕过站点限制。
- 区分“当前浏览器退出登录”和“撤销共享账号”。显式共享撤销写入 tombstone 并递增 epoch，阻止旧浏览器随后发布旧凭据复活该版本；同时取消自动恢复，并对当前已绑定实例执行受控清除/重新登录提示。
- 本地撤销不能保证网站服务器上的其他设备 token 同步失效。需要全端登出时由网站提供能力，另行授权执行。
- 显式登录态 `forget` 只处理调用者有权限的逻辑记录；旧版任意文件名删除接口不得绕过范围或绕过撤销语义。

## 6. 下载、截图共享文件库

### 6.1 目录和索引（拟新增）

```text
<DSH_HOME>/data/browser-live/
  <sessionShort>/downloads/           # 继续用每会话私有下载暂存区
  shared/v1/scopes/<scopeId>/
    auth/                            # 与产物检索完全分离
    artifacts/
      objects/<artifactId>/data.bin   # 不可变文件；原始文件名仅存 metadata
      metadata/<artifactId>.json      # 原子提交，可重建索引
      .staging/                      # 尚未发布的临时对象
    audit/                           # 脱敏操作记录
```

- 统一入口，不等于所有容器共同写一个 Downloads。保留原暂存目录可避免同名覆盖、半下载文件互见及容器对共享库的任意篡改。
- 文件记录至少包括：`artifactId`、`scopeId`、类型、原始文件名、字节数、SHA-256、创建时间、来源会话/浏览器 generation、提交状态。来源 URL 默认省略或只记录 origin（不含 userinfo、path、query、fragment）；确需路径时使用站点级脱敏规则，URL path 也可能含 token、重置码或个人信息。审计同样遵守此规则。
- 原始文件名仅作展示元数据，不参与对象目录拼接；导出时生成经过校验的安全 basename，显式目标路径仍经过工作区授权。metadata/audit 显示时转义文件名中的控制字符，避免日志或工具输出注入。
- 同名文件生成不同 ID，不覆盖；哈希去重仅限同 scope，不对无权范围泄露文件是否存在。初版可以不做去重。
- 文件内容先写 staging，完成校验和 fsync/原子提交后发布 metadata；只有 metadata 已提交的对象可检索。中断的临时文件不当成已完成产物。
- 下载完成以浏览器下载完成事件/可验证的完成结果为依据，排除 `.crdownload` 等临时文件；仅靠“大小两次没变化”不构成可靠完成证明。

### 6.2 采集覆盖

| 来源 | 初版处理要求 |
|---|---|
| 原生 open/fetch/recipe 截图 | 通过统一产物写入器登记；保留原响应可读路径，并增加 artifactId |
| Chromium 默认下载目录 | 受管容器运行时维护完成事件采集；宿主暂存区做补偿扫描，断线重连后可补登记 |
| MCP 截图、PDF、其他文件 | 当前 MCP 可继承会话工作目录，已有网关截图测试只证明图片块转发，不证明落盘；预检核实 output-dir 和返回结构，指定会话级受管输出根，并从明确完成结果归集 |
| gateway_call 中的文件工具 | 必须与直接 MCP 调用走相同归集规则，不能成为旁路 |
| 模型显式指定任意 filename/输出路径 | 不扫描或导入任意宿主路径；只自动归集白名单根内的普通文件；其他路径显示未归集原因 |
| 旧下载、旧截图 | 先只读盘点、归属确认和去重，再复制入库；保留旧源，避免历史链接失效 |
| tracing/video 等长录制产物 | 仅完成/关闭后归集；若当前版本无法验证，则明确不在初版保证范围，不假装等同截图覆盖 |

采集器不依赖浏览器工具持续调用：用户手动下载、agent 已闲置时完成的下载也应可发现。无法证明完成的候选保留在暂存区并显示 pending，不发布半成品。

### 6.3 工具契约与权限

拟新增一个统一的 `browser_live_artifact` 工具，动作限定为 `list/info/save`，参数使用 artifactId、类型和分页；默认仅列出调用者可信 scope 内的已发布文件。**查询不拉起浏览器。**

- 现有 `browser_live_download list/save` 保留兼容：原来按当前会话文件名的语义不静默改变；可新增显式共享查询方式，或引导使用 artifactId 的统一工具。
- `save` 从共享对象复制到当前会话允许的工作目录；目标路径必须经过宿主文件写入授权/沙箱校验，不使用裸 `fs.copyFileSync` 规避政策，不默认覆盖已有文件。
- 来源路径也校验 realpath、所属根和普通文件类型，拒绝路径穿越、符号链接逃逸、设备文件及指向 auth 仓库的链接。
- 原 MCP 返回的图片、structuredContent、取消语义和原生 screenshotPath 保持兼容；共享失败不能谎报成功，也不能吞掉原始浏览器结果。返回 `captured=true, published=false` 及可重试原因。
- 初版不增加任意目录扫描、跨范围移动或共享库批量删除工具。截图/下载可能含敏感信息，只在已授权范围自动发布；登录态 JSON 不得进入产物库。

### 6.4 保留与配额

- 首版不自动删除已发布对象；按范围统计磁盘用量、孤立 staging、候选下载和失败重试数量，并提供清理预览。
- 达到已配置硬配额时停止新发布、保留来源并明确告警；不通过删除历史文件或凭据来悄悄腾空间。
- 后续若启用过期清理，需单独确认保留天数、固定保留/pin、引用检查和删除授权。浏览器 TTL 不得复用为文件 TTL。
- 本项目只管理带有本项目归属元数据的对象；不执行全局 Docker prune、全局临时目录清扫或按容器名前缀批量删除。

## 8. 实施顺序与门禁

### P0：冻结基线与技术可行性（先做，不直接投产）

- 保护既有未提交改动；核对部署源、依赖版本、共享范围身份来源、文件沙箱接入点。
- 用虚构站点和虚构凭据验证 Cookie/localStorage 首请求恢复、新页面/重定向、账号冲突和可选 IndexedDB；不读或复制真实凭据。
- 验证两条工具路径以及 gateway_call 的统一拦截，MCP output-dir/文件返回、下载完成事件能否工作。
- 输出能力矩阵：支持/受限/不支持。确认测试是否需要额外宿主能力、端口和 Docker 权限。
- **G0 放行条件：** 可信 scope 可验证；受支持登录态能在页面脚本之前恢复；MCP/原生均无旁路；产物完成信号可靠。若不满足，先修订方案，不把未知能力写成实现承诺。

### P1：独立池与安全共享底座

- 实现全槽位独立、lease/回收状态机和映射迁移，不自动删除旧实例。
- 实现 scope resolver、仓库版本、原子提交、CAS、撤销 epoch、权限和脱敏审计。
- 完成单元测试与故障注入测试；共享功能仍关闭。
- **G1 放行条件：** 无 legacy 串用；busy 不被淘汰；并发提交、重启恢复、删除失败均不会丢失追踪或跨范围访问。

### P2：共享文件闭环（可与 P3 在 P1 接口冻结后并行）

- 实现下载/截图归集、统一查询和受授权的工作区复制；兼容旧工具响应。
- 纳入已验证的 MCP 截图/PDF 路径，显式标记未覆盖类别。
- **G2 放行条件：** A 生成、B 读取/保存成功；同名、半下载、路径穿越、无权范围、磁盘满和重启补偿用例通过；文件查询零浏览器拉起。

### P3：共享登录态闭环

- 先上线显式绑定、发布、恢复和撤销；再接入已绑定账号的自动恢复。
- 自动发布按站点独立启用，初版不全局开启。实现冲突提示、过期提示与身份可见性。
- **G3 放行条件：** A 登录发布、B 独立实例恢复；首请求检查通过；A/B 标签页互不影响；不同账号不串用；过期、撤销及旧客户端迟到提交均安全拒绝。

### P4：迁移演练、灰度与回滚

- 先在隔离环境演练，再对一个明确可信范围开启共享；不得直接复用真实账号作为自动测试数据。
- 迁移旧状态/文件只复制不删除；留存清单和哈希；验证停用共享后旧功能仍可使用。
- **G4 放行条件：** 全量验收矩阵通过；无测试资源残留；旧数据可恢复、回滚演练通过；用户另行授权后才切换实际运行环境。

## 9. 历史数据迁移与回滚

### 9.1 迁移

1. 只读盘点容器、map、profile 卷、旧 states、下载/截图目录、权限和用量；每项标明归属明确/待确认。无挂载不代表无价值。
2. 确认要共享的网站/账号及可信范围。旧 profile 不整卷公开、不与新会话共同挂载；通过允许的存储 API 导出受支持部分。
3. 如必须复制浏览器 profile，只在停止对应写入者并取得操作授权后做一致性备份；不能对运行中的 Chromium 卷直接做可信迁移副本。
4. 登录态迁移为受权限控制的 v1 revision；旧 states 未确认来源时留在原处，不自动发布。历史文件复制入库，记录来源及哈希，旧路径不删除。
5. 切换时先停止新分配并等待在途操作，保存旧 map/配置及其校验清单。把旧实例停放到独立旧资源清单，保持端口不冲突，再启用新池。
6. 任何停止/删除旧容器、卷、目录都需另外确认精确对象。迁移成功不自动触发删源。

### 9.2 回滚

触发条件：串号/越权、文件丢失或覆盖、自动发布污染凭据、恢复失败率明显上升、容器持续失联或无法可靠回收。

- 立即禁止新共享导入/发布，并冻结故障版本；暂停新分配，排空在途操作。
- 区分两种回滚：仅停用共享可保留新独立池；回退旧代码必须停用新 generation 并使用备份的旧 map/配置，旧代码不得读取新版 map/共享仓库。
- 保存新增产物和登录态 revision，不把回滚等同于删除新数据，不用旧快照覆盖用户在切换后产生的文件。
- 若发生凭据越权或复活，先撤销受影响绑定、清除受控浏览器导入状态，必要时由用户在网站端撤销 token；仅切配置不能撤回已泄露凭据。
- 恢复旧实例前逐项确认端口、容器名、卷和路由占用；完成浏览器工具回归后再开放流量。
